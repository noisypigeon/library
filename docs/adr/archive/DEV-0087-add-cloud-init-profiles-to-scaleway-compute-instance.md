# DEV-0087: add cloud-init profiles to `scaleway/compute-instance`

- **Author**: Willow Finch ([@noisypigeon](https://github.com/noisypigeon)).
- **Date**: 2026-10-01.
- **Status**: Accepted.

## Context

`scaleway/compute-instance`'s cloud-init body (`local.cloud_init` in `instance.tf`) has always been a single, unconditional shape: every instance gets `rclone`+`neovim` installed and `/root/.config/rclone/rclone.conf` written from `var.buckets` (ADR-0081, CHANGELOG 0.2.0), and — since CHANGELOG 0.6.0 — a `build-essential`/`pkg-config`/`libssl-dev` toolchain plus [mise](https://mise.jdx.dev/), also unconditionally. There's no way to opt out of any of this, and no way to provision an instance for a different purpose (e.g. a Docker host) without it also getting an unused rclone setup and a build toolchain it doesn't need.

The user wants a `profile` variable to select between two provisioning shapes: `"rclone"` (today's rclone/bucket behavior) and `"docker"` (install Docker CE instead). Separately, `build-essential`/`pkg-config`/`libssl-dev` are dropped entirely — they were only ever added to support `mise` installing/building something, not rclone, and aren't needed by either new profile.

## Decision

### New `profile` variable, default `"rclone"`

```hcl
variable "profile" {
  type        = string
  description = "Cloud-init provisioning profile: \"rclone\" (rclone/neovim + rclone.conf) or \"docker\" (Docker CE)"
  default     = "rclone"

  validation {
    condition     = contains(["rclone", "docker"], var.profile)
    error_message = "profile must be \"rclone\" or \"docker\"."
  }
}
```

Defaults to `"rclone"` to preserve current behavior for every existing caller — consistent with this module's established pattern of every prior addition (`buckets`, `enable_ipv6`, `ssh_keys`, `additional_volume_ids`, `enable_ipv4`) staying optional and default-preserving. This is what makes the change `release:minor` rather than a breaking change.

### `local.cloud_init` branches on `var.profile`

`packages:` and `runcmd:` sections grow `%{if}/%{endif}` template directives rather than becoming separate per-profile heredocs — keeping one rendered string so the existing `terraform_data.cloud_init` md5-hash + `replace_triggered_by` force-replace mechanism (ADR-0084) continues to work unchanged; it already force-replaces on any change to the fully-rendered string, regardless of which branch produced it.

- **`profile = "rclone"`**: `packages:` gets `rclone`+`neovim` (unchanged from today, minus the removed build toolchain); `write_files:` writes `/root/.config/rclone/rclone.conf` from `var.buckets`, identical to ADR-0081's rendering (one `alias` + one `s3` remote per bucket).
- **`profile = "docker"`**: `packages:` gets the standard Docker apt-bootstrap dependencies (`apt-transport-https`, `ca-certificates`, `curl`, `gnupg`, `lsb-release`); `runcmd:` adds Docker's official apt key + repo and installs `docker-ce docker-ce-cli containerd.io docker-compose-plugin`, then enables and starts the service.
- `build-essential`, `pkg-config`, `libssl-dev` are removed outright, under both profiles — they existed only to support `mise`'s build-toolchain use case (CHANGELOG 0.6.0), not rclone, and aren't relevant to either new profile.
- `mise`'s install `runcmd` (the curl-install line + `.bashrc` activation) stays common to both profiles — it's unrelated to the rclone-vs-docker choice.

The user's initially-proposed Docker bootstrap had three bugs, fixed here rather than copied verbatim:
- The GPG key URL and apt repository URL both pointed at `https://docker.com` — corrected to Docker's real `https://download.docker.com/linux/ubuntu/...`.
- The keyring list path had a typo, `/etc/apt/sources.list.p/docker.list` — corrected to `/etc/apt/sources.list.d/docker.list`.
- The apt repo line hardcoded `arch=arm64` — corrected to `arch=$(dpkg --print-architecture)` so the module works on any Scaleway instance type, not just arm64 ones.

`package_update`/`package_upgrade` stay `true`/`false` for both profiles (not `true` for docker, as the user's proposed snippet had it) — a full apt upgrade on every boot is slow and was deliberately avoided when this module was first built; `docker-ce` installs correctly without it.

### `buckets` gains a profile-aware guard

```hcl
  validation {
    condition     = var.profile == "rclone" || length(var.buckets) == 0
    error_message = "buckets is only used when profile = \"rclone\"."
  }
```

Configuring `buckets` on a `profile = "docker"` instance would silently do nothing (rclone never installs to consume it) — the same kind of composition-hazard guard this repo has added before for `scaleway/iam-policy` (ADR-0066, ADR-0069) rather than letting a caller misconfigure something that quietly no-ops.

### No manual `README.md`/`CHANGELOG.md` edits

Both are regenerated by this repo's existing automation on merge — `module-docs.yml` rebuilds the inputs/outputs table from `inputs.tf`'s descriptions, `module-release.yml` creates the `CHANGELOG.md` entry from the PR title/body. No ADR in this module's history has hand-edited either file.

## Consequences

- `release:minor` — `profile` is a new, optional, default-preserving input; existing callers are unaffected by the interface itself.
- Behavior change within the default profile: any existing caller relying on `build-essential`/`pkg-config`/`libssl-dev` being present (e.g. to compile something via `mise`) loses them on their next apply, even though they didn't change any input. This is called out explicitly since it's not purely additive, even though it ships as `release:minor` per this repo's established "new/expanded input → minor" convention (CHANGELOG 0.5.0/0.6.0 precedent: unconditional provisioning changes with no interface break still ship as minor).
- Cloud-init content changes on every profile → every existing instance using this module gets replaced on its next `terragrunt apply` after upgrading, per the existing force-replace lifecycle (ADR-0084). This is true of any change to `local.cloud_init`, not specific to this ADR.

## Out of scope

- A third profile (e.g. a `"bare"`/no-op profile that installs nothing extra) — add if/when needed.
- Docker sub-configuration (compose version pinning, `daemon.json`, registry mirrors, non-root `docker` group membership) — this ADR only bootstraps Docker CE itself.
- Making `profile` a `list(string)` to combine rclone+docker on one instance — today's `%{if}` branching assumes mutually exclusive profiles; revisit if a real use case needs both.
