# DEV-0136: move short module-source redirect URLs from `noisypigeon.com` to `pigeon.dev`

- Status: Accepted
- Date: 2026-10-06
- Author: Willow Graysen ([@noisypigeon](https://github.com/noisypigeon)).

## Context

ADR-0109 added short `noisypigeon.com/modules/<provider>/<module>/vX.Y.Z` URLs so a
`source =` line can read as a stable, human-typeable address instead of a long
`git::https://github.com/...?ref=...` string; ADR-0110 moved the modules themselves
to `templates/terraform/` but kept the public URL's `modules/...` path fixed
regardless of which internal prefix a tag actually lives under, decoupling the public
namespace from the repo's own layout; ADR-0114 extended the same generator with a
second, human-facing (not build-input) redirect for `templates/zola-site`
(`noisypigeon.com/templates/zola-site/vX.Y.Z`). All three pages are generated by
`workloads/noisypigeon.com/generate-module-redirects.sh` as static Zola content and
served from `noisypigeon.com` — this repo's personal-blog domain.

`pigeon.dev` has since gained its own Terraform self-sufficiency (ADR-0130) and now
runs the identical Zola + `templates/zola-site` theme + Scaleway-bucket-behind-
Cloudflare hosting pipeline as `noisypigeon.com` (`workloads/pigeon.dev/src/`,
`.mise.toml`'s `pigeon-dev-build`/`pigeon-dev-serve` tasks,
`.github/workflows/pigeon-dev-pages.yml`) — currently serving nothing but a
placeholder "wiki" page. Developer-tooling redirect URLs are a better fit for
`pigeon.dev` than for the personal blog; this ADR moves them there and updates every
consumer in this repo to the new host.

Confirmed before deciding anything:

- `generate-module-redirects.sh` has no hardcoded domain anywhere in its logic — the
  full public URL is formed by Zola combining each generated page's relative
  `path = "modules/..."`/`"templates/..."` with whichever site's `config.toml`
  `base_url` it builds under. Moving the script's *target site* is the entire
  domain change; the tag-matching allowlist and `git_source`/`github_url`
  construction (which reference `github.com/noisypigeon/noisypigeon`, the repo
  slug — unrelated to the redirect's own host) need no change.
- `pigeon.dev` needs zero new Terraform resources: its existing `wiki/bucket` +
  `wiki/dns` + `wiki/iam` leaves already serve whatever Zola builds into `public/`.
- A live `grep -rl "https://noisypigeon\.com/modules" --include="*.tf" .` is the
  authoritative consumer list: 31 files, 42 `source =` lines — 29 are
  `workloads/*/terraform/**` leaves, 2 are `templates/terraform/scaleway/
  compute-instance/{iam.tf,instance.tf}` (that module's own internal composition of
  `iam-policy`/`iam-api-key`/`block-volume` via the short URL).
- `workloads/root.hcl`'s leaf-validity guard and per-leaf credential/region
  branching are purely path-shape-derived (ADR-0092/0096/0124) — this change creates
  no new leaf path, so it needs zero changes.
- The `git::...?ref=...` target every short URL resolves to is byte-identical before
  and after this change — only the human-typed redirect hostname changes — so no
  module needs a version bump *because of* this change. The one exception:
  `template-release.yml`'s changed-module detection reacts to any `.tf` diff inside a
  directory with prior tags, with no label gating on whether a release fires at all
  (a label only picks the bump size, defaulting to `patch`). `compute-instance`
  already has prior tags (`v5.3.0`), so editing its `iam.tf`/`instance.tf` will
  unconditionally cut a real `v5.3.1` patch release once that PR merges — accepted
  as an intentional, documented side effect, not something to engineer around.

## Decision

### Relocate the mechanism to `workloads/pigeon.dev/`

`git mv`:
- `workloads/noisypigeon.com/generate-module-redirects.sh` → `workloads/pigeon.dev/generate-module-redirects.sh`
- `workloads/noisypigeon.com/src/templates/module-redirect.html` → `workloads/pigeon.dev/src/templates/module-redirect.html`
- `workloads/noisypigeon.com/src/templates/theme-redirect.html` → `workloads/pigeon.dev/src/templates/theme-redirect.html`
- `workloads/noisypigeon.com/src/content/modules/_index.md` → `workloads/pigeon.dev/src/content/modules/_index.md`
- `workloads/noisypigeon.com/src/content/theme-versions/_index.md` → `workloads/pigeon.dev/src/content/theme-versions/_index.md`

Inside the moved script, only `CONTENT_DIR`/`THEME_CONTENT_DIR` and the header
comment's domain mention change, from `workloads/noisypigeon.com/src/content/...` to
`workloads/pigeon.dev/src/content/...`. `.gitignore`'s four whitelist/ignore lines
for the generated (gitignored) `.md` pages move the same way.

### Rewire build and CI invocation

- `.mise.toml`: drop `../generate-module-redirects.sh` from `blog-build`/
  `blog-serve`; add it (after `resolve-theme.sh`, before `zola build`/`zola serve`)
  to `pigeon-dev-build`/`pigeon-dev-serve`.
- `.github/workflows/noisypigeon-com-deploy.yml`: drop the "Generate module redirect
  pages" step.
- `.github/workflows/pigeon-dev-pages.yml`: add the equivalent step — its checkout
  already has `fetch-depth: 0`/`fetch-tags: true` (present but previously unused by
  anything), which now becomes load-bearing.
- `.github/workflows/template-release.yml`: retarget "Trigger blog deploy"'s
  `gh workflow run noisypigeon-com-deploy.yml --ref main` to
  `gh workflow run pigeon-dev-pages.yml --ref main`. This dispatch exists solely so
  a freshly-cut module/theme tag's redirect page goes live promptly without a direct
  push to the site's own `src/**`; that page now lives on `pigeon.dev`.

### Update every consumer

All 42 `source =` lines across the 31 files above get their
`https://noisypigeon.com/modules/...` prefix replaced with
`https://pigeon.dev/modules/...` — a pure literal substitution; every consumer's
resolved `git::...?ref=...` target, and therefore its actual Terraform behavior, is
unchanged. Documentation mentions of the short-URL pattern in `templates/terraform/
README.md`, the `iam-policy`/`cockpit-observability`/`iam-application`/
`iam-api-key`/`compute-instance` module READMEs, `templates/zola-site/README.md`, and
this file's own `templates/terraform/` structure paragraph move the same way. Past
ADR bodies (0109/0110/0113/0114/0132), every `CHANGELOG.md`'s existing entries, and
the on-site changelog post from 2026-10-03 are left untouched, matching this repo's
established precedent of not rewriting historical record (ADR-0108).

### Land as two sequential PRs

Mirroring ADR-0110's own precedent of splitting a move into a "mechanism" PR and a
"mechanical consumer sweep" PR: one PR carries the ADR, the mechanism relocation, the
`compute-instance` edits, and docs — touching `templates/terraform/**` (so
`template-release.yml` fires, cutting `compute-instance` v5.3.1) and
`workloads/{noisypigeon.com,pigeon.dev}/src/**`, but no `workloads/*/terraform/**`
path, so `terragrunt-plan.yml` does not fire. The second PR carries only the 29-file
`workloads/*/terraform/**` sweep — triggering `terragrunt-plan.yml`/
`terragrunt-apply.yml` (expected: "No changes" on every leaf) and its auto-merge gate
(ADR-0129/0134), with no `templates/**` path to trigger `template-release.yml`. The
first PR merges and deploys before the second opens, so the second PR's new URLs
already resolve by the time it lands.

## Consequences

- Every `noisypigeon.com/modules/...` and `noisypigeon.com/templates/zola-site/...`
  redirect page is removed from `noisypigeon.com` and now lives at the equivalent
  `pigeon.dev/...` path, serving identical `terraform-get`/refresh content.
- `compute-instance` gets a `v5.3.1` patch release as an accepted side effect of the
  existing release automation reacting to a real, if purely cosmetic, edit to its
  tracked content — not a deliberate module change.
- Every `workloads/*/terraform/**` consumer's `source =` line now points at
  `pigeon.dev`; the git ref each resolves to is unchanged.
- `noisypigeon.com` itself is otherwise untouched — only the developer-tooling
  redirect layer moves off it.
- `workloads/root.hcl` required zero changes.

## Out of scope

- A compatibility redirect from old `noisypigeon.com/modules/...`/
  `noisypigeon.com/templates/...` URLs to the new `pigeon.dev` ones, for any consumer
  with a stale pinned `source =`. This repo's own modules are the only known
  consumers and all are updated in the same effort; not worth tracking as a gap
  unless an external consumer surfaces later.
